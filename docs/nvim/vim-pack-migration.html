vim.pack の概念と移行計画

lazy.nvim をやめて標準の vim.pack に移行するための学習ドキュメント。概念 → API → lockfile → 移行手順 → 日々の運用、の順に読めば実装イメージが持てます。

nvim v0.12.4 (nix) plugins: oil.nvim / mini.icons catppuccin 同梱済み

1. 全体像 — 何が変わるのか

lazy.nvim は「spec 形式・遅延ロード・lockfile・UI」を提供する外部プラグイン。vim.pack は Neovim 本体組み込みの最小構成マネージャで、git clone + lockfile + 更新確認バッファを提供します。遅延ロード機械はないので、「全部起動時に読む」現在の使い方と相性が良い。

失うもの

  • opts = {} 自動 setup 慣習 → 明示的に setup() を呼ぶ
  • 遅延ロード（現状未使用なので実質影響なし）
  • { import = "plugins" } の自動スキャン → 自前で require
  • 0.12.4 では :packupdate コマンドなし（Lua API で運用）

得られるもの

  • bootstrap コード不要（本体機能なので消える）
  • lockfile はネイティブ (nvim-pack-lock.json)
  • 設定ファイル総量の減少・依存ゼロ
  • PackChanged イベントでのフック（build 等）

前提メモ: catppuccin は 0.12 から runtime 同梱（$VIMRUNTIME/colors/catppuccin.vim 実機確認済み）。colorscheme catppuccin はそのまま動き続けます。

2. 基礎概念 — Vim packages

vim.pack を理解するには、まず Vim 由来の「package」システムが必要です。これは :h packages の世界。

~/.local/share/nvim/
└── site/pack/{pack名}/
    ├── start/{plugin名}/   ← 起動時に自動ロード
    └── opt/{plugin名}/    ← :packadd {plugin} で明示ロード

vim.pack 管理下:
└── site/pack/core/opt/{plugin名}/   ← 常に opt として置かれる

'runtimepath'

Nvim が ftplugin / colorscheme / lua モジュール等を探す場所のリスト。pack/*/start/* は暗黙で検索対象になる（&rtp 表示には出ない）。

start vs opt

start 配下は起動時に plugin/ スクリプトまで自動 source。opt 配下は rtp 探索のみ有効で、:packadd! するまで plugin/ は読まれない。

vim.pack は opt 前提

インストール先は常に core/opt。add() 内で :packadd 相当を実行して初めて使えるようになる、という設計。

3. vim.pack API — 4 つの関数だけ

0.12.4 の vim.pack は関数 4 つ（実機確認: add / del / get / update）。これだけでインストール〜更新〜削除が完結します。

-- インストール & ロード（並列 clone、完了まで同期）
vim.pack.add({
  { src = 'https://github.com/nvim-mini/mini.icons' },          -- 文字列でも可
  {
    src = 'https://github.com/stevearc/oil.nvim',
    name = 'oil',                        -- ディレクトリ名（省略時は repo 名）
    version = 'master',                  -- ブランチ / タグ / コミット / vim.version.range()
  },
}, {
  confirm = false,                       -- 初回インストールの対話確認を省略（デフォルト true）
})

require('mini.icons').setup({})          -- opts={} 自動化はないので明示 setup
require('oil').setup({})

vim.pack.update()

差分確認バッファ（タブページ）を開く。:write で適用、:quit で取消。LSP 経由で gx リンクや K hover 付き。

vim.pack.get()

各プラグインの rev / rev_to / tags 等を取得。rev ~= rev_to なら保留中の更新あり。

vim.pack.del()

ディスクから削除。spec から外して再起動した後に呼ぶ。非アクティブなものは { force = true } 不要で削除可能。

add() の load オプション — ハマりどころ

init.lua 読み込み中はデフォルト load = false（:packadd! 相当 = rtp 追加のみで plugin/ スクリプトは source しない）。init.lua 以降では true。今回は両プラグとも setup() を明示呼びするので問題ないが、plugin/ スクリプト必須のプラグインを入れるときは意識する。

5. lockfile — 再現性の中核

生成と場所

  • 最初の vim.pack 関数呼び出し時に自動生成
  • パスは $XDG_CONFIG_HOME/nvim/nvim-pack-lock.json 固定（0.12.4。master では 'packlockfile' オプション化）
  • ~/.config/nvim は symlink なので実体はこのリポジトリ内 → VCS 管理できる（推奨）
  • lockfile がある環境では記載リビジョンで一括インストールされる

ライフサイクル

  1. config 変更後 :restart → spec と lockfile を突き合わせ
  2. vim.pack.update() で差分確認 → :write
  3. lockfile 差分をコミット
  4. 他マシンでは pull 後 :restart で lockfile 通り復元
# ロールバック: 直前の更新を取り消す
git checkout HEAD -- nvim-pack-lock.json
# → nvim で:
vim.pack.update(nil, { target = 'lockfile' })   -- 確認して適用

# freeze: spec.version を現在の rev に固定すると更新されなくなる
{ src = '...', version = 'abc12345' }
# unfreeze: version を nil / ブランチ等に戻す

6. 移行ステップ 1 — 機械的置換

構造はいじらず、同じ挙動になることだけを目指す。

削除

  • lua/config/lazy.lua (bootstrap)
  • lua/plugins/filer.lua (lazy spec)
  • lazy-lock.json (代替は nvim-pack-lock.json)

変更

  • init.lua: require('config.lazy') → require('plugins')
  • 新規: lua/plugins/init.lua（下記）
-- lua/plugins/init.lua （新規）
vim.pack.add({
  { src = 'https://github.com/nvim-mini/mini.icons' },
  { src = 'https://github.com/stevearc/oil.nvim' },
}, { confirm = false })

require('mini.icons').setup({})
require('oil').setup({})

検証コマンド

# エラーなし起動 + lockfile 生成確認
nvim --headless +qa && cat .config/nvim/nvim-pack-lock.json

# :Oil コマンドの存在確認（期待値 1）※ setup 由来のはず
nvim --headless +'lua print(vim.fn.exists(":Oil"))' +qa

# ディレクトリが oil で開けるか（期待値 oil）
nvim --headless +'edit /tmp' +'lua print(vim.bo.filetype)' +qa

:Oil が無ければ add() に load = true を追加して再確認。

7. 移行ステップ 2 — プラグインごとのファイル分割

規約: 「spec + setup を 1 ファイルに閉じ込める」。新しいプラグイン = ファイル 1 枚追加 + order への追記。

lua/plugins/
├── init.lua         -- 集約: add → 全 setup の順に実行
├── mini-icons.lua   -- pack + setup
└── oil.lua          -- pack + setup
-- mini-icons.lua
return {
  pack = {
    src = 'https://github.com/nvim-mini/mini.icons',
  },
  setup = function()
    require('mini.icons').setup({})
  end,
}
-- oil.lua
return {
  pack = {
    src = 'https://github.com/stevearc/oil.nvim',
  },
  setup = function()
    require('oil').setup({})
  end,
}
-- init.lua
local order =
  { 'mini-icons', 'oil' }

local mods = {}
for _, name in
    ipairs(order) do
  mods[#mods+1] =
    require('plugins.'..name)
end

local specs = {}
for _, m in ipairs(mods) do
  specs[#specs+1] = m.pack
end
vim.pack.add(specs,
  { confirm = false })

for _, m in ipairs(mods) do
  if m.setup then m.setup() end
end

依存順序

order の並びが依存グラフ（依存される側を先）。alphabetical 依存は避けて明示リストで管理。

setup 不要なもの

colorscheme 同梱系などは setup フィールドを省略すれば OK。init 側は nil チェック済み。

freeze も局所化

特定プラグインだけ固定したいときは、そのファイルの pack.version にコミットハッシュを書くだけ。

8. 移行後の日々の運用

-- 更新（確認バッファ: :write 適用 / :quit 取消）
vim.pack.update()

-- 更新の有無だけ確認（ネットワーク通信なし）
for _, p in ipairs(vim.pack.get()) do
  if p.rev_to then print(p.spec.name, p.rev, '→', p.rev_to) end
end

-- プラグイン削除（spec から外して再起動した後で）
vim.pack.del({ 'oil' })

-- build が必要なプラグインは PackChanged でフック
vim.api.nvim_create_autocmd('PackChanged', {
  callback = function(ev)
    if ev.data.kind == 'install' or ev.data.kind == 'update' then
      vim.system({ 'make' }, { cwd = ev.data.path })
    end
  end,
})

9. 注意点まとめ

0.12.4 と master の差分: 公式 Web ドキュメントは master 由来。:packupdate コマンドと 'packlockfile' オプションは 0.12.4 に存在しない（実機 help 確認済み）。0.12.4 の間は Lua API ベースで運用する。

confirm デフォルト true: 初回インストール時に対話確認が出る。headless や自動化と相性が悪いので { confirm = false } を明示。

load デフォルト（init 中 false）: plugin/ スクリプトは自動 source されない。明示 setup() で賄う前提。挙動が怪しいプラグインは load = true を試す。

初回起動はネットワーク必須: clone が走る。2 回目以降はオフライン起動可。lazy の実体は残るので、安定確認後に任意で rm -rf ~/.local/share/nvim/lazy ~/.local/state/nvim/lazy。

実験的扱いについて: help 上は WARNING: experimental だが「daily use に耐える安定度」と明記。破壊的変更は 0.x マイナーで入る可能性がある点だけ頭に入れておく。
